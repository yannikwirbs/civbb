# 0002: Phase 0 starts from glTF/VRM and generated avatars, Unity exporter later

Status: accepted; the Consequences paragraph is superseded by 0013
Date: 2026-10-28

## Context

Design doc §21 makes the Unity exporter Phase 0 deliverable 1. No Unity install exists on the dev machine and the project is AI-driven, so an exporter can be written but not run or tested by the AI.

## Decision

- Build the Rust side first: `format`, importer, compiler optimisations, `anim`, `dynamics`, viewer and benchmark.
- Input for now: glTF 2.0 and VRM 0.x/1.0 (VRM is glTF with humanoid mapping, spring bones and MToon, close to the legacy feature set), plus avatars generated by our own corpus generator, which covers the "deliberately bloated" corpus slot with assets we can commit.
- The Unity exporter (`civbb-unity-exporter` repo) is written once the source format is stable, and its testing is a `needs-user` task.

## Consequences

Animator conformance against Unity cannot run until the exporter exists. Until then, conformance uses hand-written golden files derived from documented Mecanim behaviour; they are replaced by Unity-recorded goldens later.
