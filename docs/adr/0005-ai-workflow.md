# 0005: How AI sessions track work and state

Status: accepted
Date: 2026-10-28

## Context

Every session starts with no memory. Reading the whole repo each time is slow and costly. The human owner wants to see progress without reading code.

## Decision

- Work queue: GitHub issues with labels (`area:*`, `phase-*`, `needs-user`) grouped into milestones. Milestone progress bars are the human-facing progress view.
- Session state: `docs/ai/STATUS.md` (focus, blockers, session log), `docs/ai/LESSONS.md` (gotchas), `docs/ai/NEXT_PROMPT.md` (the prompt for the next session).
- Orientation: `docs/ai/CODEMAP.md`, generated by `cargo xtask codemap` from crate descriptions and each file's first `//!` line; CI fails if it is stale or a file has no module doc.
- Rules for sessions live in `CLAUDE.md`, which Claude Code loads automatically.

## Consequences

Every file needs a one-line module doc. Session discipline (update STATUS, NEXT_PROMPT, push) is part of done.
