# 0029: Textures are atlased per material model and shipped as KTX2, encoded by basisu and transcoded in Rust

Status: accepted; codecs (point 3), mips and gutters (point 7) superseded by 0035
Date: 2026-11-03

## Context

#31: design doc §9 stage 4 atlases "textures within one material model" and compresses them to KTX2 (UASTC for
normal maps and high-quality slots, ETC1S for the rest, size caps per platform); §6 transcodes them on load to
BC7 on desktop. The doc does not pick an encoder or a transcoder, say which materials may share an atlas, or
where atlasing sits among the other stages. Runtime packages carried the source PNG and JPEG blobs, and the viewer
skipped KTX2. Draws are joined per material (ADR 0027), so two materials that differ only in their textures cost
two draws; textures are bindless (ADR 0023), so atlasing saves draws, not binds.

## Decision

1. **Encoder: `basisu_c_sys` 0.9 with its `encoder` feature**, a binding to Binomial's Basis Universal 2.x C API
   (crate MIT OR Apache-2.0, basisu Apache-2.0, as §20 lists). It vendors the C++ sources and builds them with
   `cc`; `bindgen` needs libclang, which Visual Studio ships on Windows and the Linux runners have. It writes KTX2
   directly. Not chosen: `basis-universal` 0.3 (basisu 1.16, its wrapper cannot write KTX2) and the `basisu` CLI
   (a process and an install on every runner). The C++ only ever sees RGBA arrays that the Rust `image` crate
   decoded with bounded sizes, never source bytes.
2. **Determinism:** each texture is encoded single-threaded (basisu's own threading makes UASTC RDO output differ
   between runs); textures run in parallel on their own threads. The same input gives the same bytes on one build
   host, which a test checks. Bytes across operating systems or compilers are not promised.
3. **Codecs:** a texture any material samples as a normal map is UASTC LDR 4x4 at unified quality 100 (no RDO,
   Zstandard supercompression). Everything else is ETC1S at quality 75. Effort 2, mips generated by the encoder
   with wrap filtering (the sampler repeats), sRGB from the texture's colour space. Other high-quality slots can
   move to UASTC when parity (M0.9) shows a need.
4. **Size caps:** the largest side is 4096 on desktop and 2048 on Quest; a larger texture is halved (triangle
   filter) until it fits. Atlases obey the same cap.
5. **Transcoding on load: the pure-Rust `basisu` 0.1 crate** (Apache-2.0, a port of the reference transcoder
   checked byte for byte against it) transcodes every level to BC7 on desktop, so the untrusted-input rule holds
   on the client. Our own check of the KTX2 header and level index runs first (size, level count, every level's
   range inside the file and its uncompressed length at most its blocks: `basisu` 0.1 allocates a Zstandard
   level's stated length unchecked, which a damaged file turned into a 1 EB allocation). A fuzz target and a test
   of truncated and bit-flipped files cover it. The renderer uploads the
   BC7 levels as they are, and device selection requires `textureCompressionBC` (every desktop GPU has it). ASTC
   for Quest comes with the mobile path.
6. **Who may share an atlas:** materials with the same model (PBR, Toon, Unlit) and the same set of UV-sampled
   slots. A material is left out when a clip animates any material property of a mesh drawing it (colours and
   `_MainTex_ST` alike, ADR 0025), a UV-sampled slot uses UV1 or a scale or offset other than identity, a triangle
   it draws spans more than one unit UV tile or a vertex sits in two, the textures of one material differ in size,
   or a vertex it draws is also drawn by a material that maps it elsewhere. UVs a whole number of tiles away from
   0..1 (common in Unity exports: AliciaSolid's V runs 1 to 2) are shifted back; the repeating sampler made them
   equal. Matcaps are sampled by normal, not UV: they are
   never atlased and must be the same texture. A texture is atlased only when every use of it (menu icons too) is
   a UV slot of an eligible material in the same atlas, so atlasing never duplicates texels; these rules repeat
   until nothing changes. Sampler wrap is not a separate rule: the format has one repeating sampler and UVs
   inside 0..1 never wrap.
7. **Packing:** each distinct tuple of slot textures is one rectangle with an 8-texel gutter that repeats its
   edge texels (clean down to mip 3), placed on 4-texel boundaries (BC7 blocks) by shelf packing into the
   smallest atlas within the cap. Slots whose textures are the same in every rectangle share one atlas image.
   Rectangles that do not fit start another atlas. An atlas is kept only if it lets two materials become one:
   materials of one atlas that are equal apart from their textures are then identical, and their submeshes point
   at one of them. Unreferenced materials, textures and blobs are removed. Atlases are written as PNG and
   encoded with everything else.
8. **Stage order in `civbb build`:** `prune`, `atlas`, `merge`, `collapse`, `compress`. Atlasing runs before
   merging so the materials it unifies are joined into one draw by `merge` (ADR 0027).
9. **Proof:** tests check that every vertex UV samples the same texel through the atlas as before (exactly, on
   the PNG atlas), that KTX2 decodes within each codec's error, that packages shrink, that encoding is
   reproducible, and that ineligible materials stay apart. The viewer shows AliciaSolid textured from KTX2.

## Consequences

- AliciaSolid: one atlas, textures 7 to 3, materials 12 to 10, draws 13 to 12, package blobs 5.6 MB to 2.8 MB;
  KTX2 colours at its vertex UVs differ from the source by 1.6 levels on average (99th percentile 12). The VRM
  1.0 twist sample: one atlas, 6 fewer materials, 4.8 MB to 3.3 MB. Seed-san: no atlas, 8.6 MB to 4.9 MB.
- The build needs a C++ compiler and libclang. Encoding is the slowest stage (about a second per 512 texels
  squared with mips, single-threaded); the parallel threads hide most of it, but one large atlas is one thread
  (AliciaSolid builds in 30 s instead of 8).
- ETC1S is lossy: colour texels move by a few levels, more at sharp edges. A mip-3 gutter means distant mips can
  bleed between rectangles; accepted, revisit with parity scoring.
- Materials that differ in a colour or a float never share a draw; baking such differences into textures is a
  later optimisation.
- The VRAM budget manager and mip streaming (§6) are not part of this; the caps are a stopgap until they exist.
